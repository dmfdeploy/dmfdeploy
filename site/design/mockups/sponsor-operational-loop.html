01 / Strategic value

A common layer creates room to move.

Sponsorship backs shared engineering that organizations can inspect and shape through public technical participation. The value is a stronger foundation for the field, rather than a private feature queue.

01 · MANUFACTURERS

Build against clearer boundaries.

Help inform integration points and evaluate how functions behave in a vendor-neutral deployment environment.

02 · BROADCASTERS

Make operations easier to reproduce.

Support workflows, visibility and documentation that engineering teams can assess on their own terms.

03 · INTEGRATORS

Share the hard-won field knowledge.

Contribute deployment and lifecycle experience to a reference path others can inspect and improve.

04 / Governance & independence

Support does not buy control.

The technical direction remains community-led. Sponsorship would sustain shared work under public rules, with safeguards still to be formalized.

Current practice

Open technical review

Project discussions and RFCs are public, architecture decisions are recorded, changes receive maintainer review and contributions carry DCO sign-off. The code is Apache-2.0 licensed.

Proposed safeguard

Founder-protected mission

A mission charter and sponsor boundaries are intended to protect vendor neutrality and open participation. The charter and any formal governance structure are not yet ratified.

Proposed principle: financial support would not grant a vote, veto, exclusive feature priority or control of technical direction.
